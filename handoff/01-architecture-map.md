## 3. 확장 패널 상태 (rorr-extension `docs/03` §2)

| 상태 | 조건 | 패널 |
|---|---|---|
| S0 첫 실행 | 설치 직후 | 인사 → 팀 칩 → 팀 모드 진입 |
| S1 평시 | 경기 없음·비지원 호스트 | Muse 채팅 + 다음 응원 팀 경기 카드 |
| S2 매칭 | 지원 호스트(YouTube·치지직·SOOP·Twitch) + 진행 경기 | 자동 매칭 → 실패 시 선택 → 지연 보정 1탭 |
| S3 경기 중 | 매칭 완료 | 매치 스트립 · 예고 배너 · Muse · 퀴즈 · 빠른 반응 · Boost |
| S4 세트 사이·경기 후 | 세트 종료 | 리캡, 세트 사이 한정 "웹에서 Spark 받기" |
| S5 비지원 리그 | LCK 외 | 준비 중·알림 신청 |

- 하단 구성(v45): 독(질문 · 오늘의 모먼트 · Boost) + 메뉴. 초기 기획의 하단 탭 Watch / Ranking / Me는 v45에서 대체(확장 handoff 02-screen-spec §0)
- 패널 크기: 설계 360px(320px 깨짐 없음), 실측 380×952px

## 4. 서버 경계

### 4-1. 클라이언트에 두지 않을 판정

| 판정 | 이유 |
|---|---|
| 재화 차감·잔액(유료/보너스 Energy, Spark) | 정산 원장 단일 기준 |
| Boost 확정 시점(의사 표시 즉시 vs 순간 발생 확인 후) | OI-13 미결 — 웹·확장 동일 로직 필수 |
| 카드 발급(순간당 1장, 멱등) · 배지 단계(같은 순간 누적) | 정책 §4 |
| 응원 포인트(순간당 1회) · 연속 응원 | 정책 §5-3 |
| 행운 박스 결과·지급 총량 | 정책 §6-1 B — 확률은 서버, 고르는 박스 위치와 무관 |
| 퀴즈 마감·정답 판정(확장) | 서버 시각 기준, 정책 §5-6 |
| 광고 보상 지급 | GAM 이벤트 수신 후 서버 1회용 토큰·일일 한도 |
| 큰 순간 알림 빈도 상한 | 웹 3분·확장 `EXT_HEADSUP_MIN_GAP` |

### 4-2. 공용 API (웹·확장 같은 DB·API)

| 영역 | 웹 | 확장 | 비고 |
|---|---|---|---|
| 인증 | 세션 | `chrome.identity.launchWebAuthFlow` | 같은 계정 |
| 잔액·Boost·원장 | ✅ | ✅ | 고지 문구 버전·시각을 Boost 기록과 함께 저장(정책 §1-2) |
| 카드·컬렉션 | ✅ | ✅ | 순간 ID 단위 멱등 |
| 응원 메시지·반응 | ✅ | ✅ | 욕설 필터·신고 큐 |
| 순위 | ✅ | 퀴즈 순위만 확장 | 응원 포인트·퀴즈 포인트 분리 집계 |
| 알림 설정 | ✅ | 동기화 | 골드+홀로그램 / 홀로그램만 / 끄기 |
| 확장 전용 | — | 매칭 · 순간 스트림(SSE/WebSocket) · Muse 대사 | OI-20 |
| 웹 전용 | 충전·환불·결제 내역·광고 월·알림함·블로그·자랑하기 | 웹 링크로 위임 | |
